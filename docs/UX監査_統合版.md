## P1: 操作を壊す・データを壊す（すべて未対応）

### 1. 範囲選択の矩形が高さ0で描画される（実測）
[CanvasStage.tsx:447](../src/components/CanvasStage.tsx:447) のタイポ。

```ts
height: Math.abs(marquee.currentMm.yMm - marquee.currentMm.yMm),  // 常に0
```

正しくは `currentMm.yMm - startMm.yMm`。ドラッグ中のラバーバンドが横線にしか見えず、範囲選択が壊れているように見える（選択自体はpointerup時の正しい計算で動くため実害は表示のみ）。1行修正で直る。

### 2. 数値入力欄を空にすると座標が0へテレポート（実測）
`PropertyPanel.tsx` の数値欄は `Number(e.target.value)` を即コミットする。`Number("") === 0` のため、値を打ち直そうと欄を空にした瞬間、X/Yなら オブジェクトが (0, y) へ飛ぶ。負数を入力しようと「-」を打った時も同様に0になる。min付きの幅・奥行は空にできず値が戻るだけだが、X/Y/角度/終点X/Yは実害が出る。
→ フォーカス中はローカルstateに持ち、blur/Enterでコミットする方式が必要。

### 3. 1キーストローク／1操作＝1 Undo履歴、かつ対象が拡大中（実測: 「1500」入力で履歴3→7）
`UPDATE_OBJECT` / `SET_PROJECT_NAME` / `SET_LAYER_NAME` / `SET_SNAP_SETTINGS` / `SET_STAGE_FRONT` / 壁関連の全編集が毎keystrokeで `commitProject` される。結果:

- X欄に「1500」と打つと椅子が 1→15→150→1500 と4回移動し、4履歴を消費
- ラベルやプロジェクト名の入力で履歴上限50件をすぐ食い潰し、本来戻りたい配置編集が履歴から押し出される
- Ctrl+Zが1文字ずつしか戻らない
- **（新規・表示スタイル編集で対象拡大）** 「塗りの濃さ」スライダーやカラーピッカーも同じ経路でcommitされる。実測: スライダーを9ティック操作しただけで履歴0→9。実際のドラッグ操作では1回の調整で数十件になり、履歴上限をほぼ食い潰す

矢印キーのNUDGEも押しっぱなしで同様に履歴を量産する。入力コミットの遅延（blur時）、同一フィールド連続編集の履歴マージ、またはスライダー系は`preview: true`相当にして確定時のみ履歴へ積む（既存の`COMMIT_TRANSIENT_EDIT`機構を流用可）などの対策が必要。

### 4. グループ化が選択・移動に効かない（実測: 片方クリックで「選択: 1 / 2個」）
`GROUP_SELECTED` は `groupId` を付けるだけで、`SELECT` はgroupIdを見ない。グループの1個をクリックすると1個だけが選択され、ドラッグしても1個だけ動く。groupIdが効くのはロックの伝播（`SET_SELECTED_LOCKED`）のみ。「グループ化」ボタンの一般的な期待（一緒に動く）と乖離しており、実質的に機能していない。

### 5. ポインター管理の不備（校正モードでのパン不可＋幽霊ポインターによるピンチ誤発動）
`CanvasStage.tsx` のポインター管理に2つの関連する問題がある。

**(a) 校正/測定/壁トレースモードでの誤操作**
`handlePointerDown` は校正/測定/壁トレースモードでは最初のpointerdownを即、点として登録する。

- **マウス**: 校正モード中はドラッグパンが一切できない（ホイールズームのみ）。ズームインして精密に2点を打ちたいのに、1点目と2点目の間で画面を動かせない。モードを抜けると `SET_MODE` が `calibPointsPx` をクリアするため、「1点打つ→パン→戻る」の回避策も使えない
- **タッチ（iPad）**: 2本指パン/ピンチの1本目が必ず点として登録される。校正モードでは2回のジェスチャーで意図しない2点が入り校正ダイアログが開く。壁トレースではゴミ頂点が入る

**(b) 幽霊ポインターによるピンチ誤発動（今回新規発見）**
`handlePointerMove` は、ボタン非押下のホバー移動でも `pointersRef` へポインターを登録する（[CanvasStage.tsx:364](../src/components/CanvasStage.tsx:364)）。登録されたエントリは pointerup でしか消えず、`onPointerLeave` でも削除されない。その状態で別IDのポインターが pointerdown すると `pointersRef.size >= 2` となり、**実際には1本しか触れていないのにピンチ判定になる**。

実測での再現（合成イベント）:
- 幽霊エントリがある状態での1本指ドラッグが、パンではなくピンチ扱いになり無反応になった
- 幽霊エントリとの距離比によってはズームが一気に吹き飛ぶ（検証中に zoom 0.0925→0.0033 への暴発を観測）

実機で起きる条件: Apple Pencilホバー対応iPad（ペンをかざした後、指でドラッグ）／タッチ対応Windowsノート（マウスホバー後にタッチ）／pointer captureが失敗し画面外でpointerupしたとき。「キャンバスが突然ドラッグに反応しなくなる」「ズームが飛ぶ」という再現困難な不具合の温床になる。**ズーム暴発した状態のビューは自動保存で永続化されるため、再起動しても直らない**（ユーザーには「図面が消えた」ように見える）。

校正精度はこのアプリの根幹（AC-001/002）であり、(a)(b)は同じポインター管理の甘さに起因する。対策: pointermoveでは既存エントリのみ更新する（`pointersRef.current.has(e.pointerId)` または `e.buttons > 0` のときだけset）、`onPointerLeave`/`pointercancel` でエントリを削除する、点登録はpointerup時（移動量が小さい場合のみ）に行う。

### 6. 回転ハンドルがタッチ不可能なサイズ（実測: 約8.8×8.8px）
ハンドルは mm空間で r=110mm の円のため、画面上のサイズがズームに比例する。既定ズーム0.04では直径約8.8pxで、タッチ推奨44pxの1/5。全体を見ながら回転させる操作がほぼ不可能。ハンドルは `8 / view.zoom` 方式（校正点マーカーと同じ）でスクリーン座標基準の固定サイズにすべき。

### 7. シンボルのクリック当たり判定が「描画線の上」だけ（新規・シンボル導入により後退）
配置物の描画がシンボル（`<use>`）に置き換わったが、pointer-eventsは既定の visiblePainted のまま。塗りのある本体部分と線の上しかクリックできず、外接矩形内の空白部分は素通りしてパン/選択解除になる。実測では椅子の上部コーナー・上辺中央が常にヒットしない。旧描画（全面rect）より選択しづらくなった明確な後退で、譜面台のような「上半分だけのグリフ＋細い棒」では footprint の大半がデッドゾーンになる。
→ 各シンボル `<g>` に透明な footprint rect（`fill="transparent"` または `pointer-events="all"`）を敷くのが確実。

## P2: 明確な不便・混乱

### 8. Escキャンセルが2D編集に存在しない
配置待機・注釈モード・範囲選択・校正の取り消しは、ツールバーの「選択」まで戻るかプリセットを再クリックするしかない。ダイアログ（校正・出力・行列・プルト）もEsc/背景クリックで閉じない。`role="dialog"` はあるが `aria-modal`・フォーカストラップもない。（3Dビューの一人称モードにはEscで俯瞰へ戻る実装がある一方、2D側は未対応のまま）

### 9. 「全体表示（フィット）」がない＋ズームボタンの中心が固定座標
- 背景読込後・校正後・JSON読込後にビューが自動フィットしない。校正で縮尺が変わると図面が急に小さく/大きくなり、手動でパン・ズームして探すことになる
- `Toolbar.tsx` の `zoomBy` はズーム中心が `(480, 320)` ハードコード。900px以下の縦積みレイアウトではこの点がキャンバス外（ツールバー/ライブラリ領域）にあり、拡大ボタンを押すたびに図面が画面外へ流れていく（タブレットで実測: キャンバスはy=434から始まる）
- ズーム倍率の表示もない

### 10. iPad縦相当（768px）でキャンバス高さが320px
縦積みレイアウトの配分が ツールバー190px＋ライブラリ244px＋キャンバス320px＋プロパティ244px。主作業領域が画面の約1/3で、ライブラリの下に埋まる。配置→プロパティ確認のたびにスクロールが必要。キャンバスを最優先（ライブラリ/プロパティは折りたたみやタブ化）すべき。

### 11. 文字注釈のインライン編集ができない（部分改善）
クリックで「注釈」という固定テキストが置かれ、内容変更は右パネルのラベル欄のみ。**改善点**: 文字・矩形注釈のラベルがtextarea化され複数行対応になった。**未対応のまま**: ダブルクリックでのキャンバス上インライン編集開始はできない。また問題3の履歴消費問題はtextarea入力にもそのまま当てはまる。

### 12. プルト弧状配置・行列配置にプレビューがない
中心X/Y・半径・開始/終了角・プルト数をすべて数値で指定し、結果は配置してみるまで分からない。特に中心座標は既定値（背景幅/2, 4000）が実際の舞台中心とは無関係で、狙い通りに出すには「配置→Undo→数値調整」の試行錯誤になる。ダイアログ背後のキャンバスへのライブプレビュー描画、または「キャンバス上で中心をクリック指定」が必要。

### 13. 複数選択をまとめて回転・スタイル編集できない
回転ハンドルは単一選択のみ。弦セクションの列をまとめて15度傾ける、といった操作ができない（1個ずつ回して整列し直すことになる）。プロパティの角度欄も複数選択時は非表示。**（新規）** 表示スタイル編集（色・塗り・線幅）も単一選択専用で、「弦全体を黒、管を青」のような一括変更ができない。

### 14. パン・ズーム状態が自動保存されない
`SET_VIEW` は `saveState` をdirtyにしないため、視点変更だけでは自動保存が走らない。作業を閉じて再開すると最後の編集時点の視点に戻る。他の編集操作のついでに巻き添え保存される挙動も同じ。問題5(b)の「ズーム暴発が意図せず永続化される」リスクと合わせて対応優先度が上がっている。

### 15. 編集系ショートカットの不足
Ctrl+C/V（コピー/ペースト）、Ctrl+D（複製）、Ctrl+A（全選択）がない。複製はパネルボタンのみで、オフセットは+500mm固定。ショートカット一覧を表示する手段もない。

### 16. 壁トレースの「1点戻す」がない
「やり直し」は全頂点破棄のみ。確定後の頂点修正は数値入力のみで、キャンバス上でドラッグできない。長い壁で最後の1点をミスすると最初からになる。

### 17. 出力ダイアログの構成
- 縮尺の説明（1:50/1:100/フィット、100%印刷の注意）が「出力」ボタンより下にあり、スクロール位置によっては読まれずに出力される
- 出力実行時に `SET_METADATA`/`SET_EXPORT_SETTINGS` がUndo履歴に積まれ、出力後のCtrl+Zで「配置が戻らずメタデータが戻る」という不可解な挙動になる
- 出力プレビューがなく、紙面にどう収まるか（フィット時の実際の縮尺）は出力してみるまで不明

### 18. ライブラリに検索・絞り込みがない
プリセットは約30種の縦一列。「ティンパニ」系が「打楽器」内の離れた位置に26"/29"と23/32インチで散在するなど、探すのにスクロールが必要。検索欄か最近使った項目があると連続作業が速い。

### 19. レイヤーが固定3枚
追加・削除・並び替え・名前変更のUIがない（`SET_LAYER_NAME` Actionは実装済みだがUI未接続）。「弦」「管」「打」を分けたい規模の編成では不足する。

### 20. 出力SVGがCSS var()のプレゼンテーション属性解決に依存（新規・要iPad Safari実機確認）
シンボルの塗り/線幅は `fill-opacity="var(--symbol-body-opacity, 0.05)"` のように**プレゼンテーション属性内のvar()**で指定され、`<use>` 先の `<g style="--symbol-body-opacity:0.92">` から継承させている。Chromium系では正しく解決されることを最小SVGのラスタライズで実測確認した。ただしこの書き方はSVG2の比較的新しい挙動で、**フォールバック値（0.05）が意図値（0.92前後）と大きく異なる**ため、未対応ブラウザ（特に旧Safari）では椅子がほぼ塗りなしで表示・出力される。iPad Safari実機での表示とPNG/PDF出力の確認リストに追加すべき。属性ではなく `style="fill-opacity: var(...)"`（CSSプロパティ）へ寄せれば互換リスクが下がる。

## P3: 軽微

- スナップ間隔欄を空にすると1mmに正規化され、意図せず極細スナップになる（他の数値欄も同種のNumber("")問題）
- ステータスバーの「履歴: n/50」は開発者向けの表現。一般ユーザーには「元に戻せる回数」等が分かりやすい
- 測定結果はモードを離れると消え、コピーもできない
- JSON保存は背景data URL込みで巨大になり、毎回ダウンロード（上書き保存の概念がない）。IndexedDB自動保存も1.5sごとに全量書き込みのため、大きなPDF背景では負荷が疑われる（未計測）
- キャンバスのホイールは常時ズーム。トラックパッドの2本指スクロールでパンしたい人には設定がない
- Undo/Redoボタンに回数や対象の表示がない（何が戻るか分からない）
- **（新規）** スタイル編集の線幅(mm)・ラベル文字サイズ(mm)欄に入力ガードがない。`Number(e.target.value)` を無検証で保存するため、空欄→0保存、範囲外の値（例: 線幅500）も一旦保存され、再読込時にのみ`resolveObjectStyle`のclampで最小/最大値に化ける。表示と保存値の食い違いが起きる
