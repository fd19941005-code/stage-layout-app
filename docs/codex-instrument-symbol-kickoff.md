# Codex開始指示：楽器シンボル再構築

新しいCodexセッションで、舞台図面作成アプリのリポジトリを開いた状態で使用する。

## 最初のメッセージ

```text
docs/instrument-symbol-spec-final-v1.2.md を読んでください。

このファイルを、今回の楽器シンボル再構築における正式な仕様書・唯一の基準として扱ってください。
ただし、正常に動作している既存機能を不用意に破棄しないでください。

今回はまだコードを変更しないでください。

最初に以下を調査し、報告してください。

1. 現在の未コミット変更と作業ブランチ
2. 楽器シンボルの描画経路
   - instrumentCatalog
   - symbols
   - CanvasStage
   - SVG読込
   - width / height
   - viewBox
   - preserveAspectRatio
   - scaleX / scaleY
   - transform
3. 現在使われている全SVGファイルの一覧
4. 配布元SVGと現行SVGの差分
5. 実ファイル名、assetId、楽器カテゴリ、使用プリセットの対応
6. 各SVGを visual / projection / preset のどれに分類すべきか
7. 現在の保存スキーマと旧データ移行への影響
8. ピアノ、バスドラム、ティンパニ、4トムで形が崩れている直接原因
9. 認証・デプロイ等、今回変更してはいけないファイル
10. 実装を安全に分割した計画

確認できた事実と推測を明確に分けてください。

次のものを提示してください。

A. 仕様と現行実装の差分
B. 変更予定ファイル
C. 新規作成予定ファイル
D. 削除候補。ただし承認前に削除しない
E. 保存データ移行案
F. テスト計画
G. 未確定点・実装上の懸念

私が承認するまで、コード、SVG、設定ファイルを変更しないでください。
認証関連ファイル、deploy設定、BetaGate等のシンボル作業と無関係な変更は含めないでください。
```

## 調査計画を承認するとき

```text
計画を承認します。

一括実装はせず、次の第1段階だけ実施してください。

1. 全SVGのアセット対応表を作成する
2. SymbolAsset と InstrumentPreset を分離する
3. visual / projection / preset の分類をデータ化する
4. 通常SVGの非等方変形を防止する
5. 既存機能を壊していないことをテストする

まだ個別楽器の全面移行には進まないでください。

実装後に以下を報告してください。

- 変更ファイル
- データ構造
- 既存保存データへの影響
- typecheck
- test
- build
- 残る問題
```

## 第2段階：問題の大きい楽器

```text
第1段階を承認します。

第2段階として、次だけ実装してください。

1. フル／セミグランドを別寸法・別輪郭にする
2. 黒塗り／白抜きを visual バリエーションとして選択可能にする
3. バスドラム36×22を正しい縦横比で実装する
4. ティンパニ23／26／29／32を円形生成する
5. ティンパニ4台セットを元SVG参照の固定弧状配置にする
6. 4トム16／14／12／10を緩い弧状配置にする
7. 比較用の校正画面またはスクリーンショットを作る

ドラムセット、ハープ、その他の楽器にはまだ進まないでください。

typecheck、test、build、保存再読込、ズーム50／100／200％を確認して報告してください。
```

## 第3段階：SVGバリエーション

```text
第2段階を承認します。

第3段階として、次を実装してください。

1. ハープA／B／Cを同一寸法の visual バリエーションとして選択可能にする
2. マリンバ、ビブラフォン、シロフォン、グロッケン、チャイムのA／Bを選択可能にする
3. アップライトピアノ、電子ピアノ、シンセ等の visual バリエーションを整理する
4. projection に分類された正面図を通常の平面配置一覧から除外する
5. バリエーション切替で寸法、位置、回転、選択枠が変わらないテストを追加する

全楽器の一括移行にはまだ進まないでください。
```

## 第4段階：残りの寸法マスター

```text
第3段階を承認します。

仕様書の全シンボル寸法マスターに従って、残る楽器を段階的に登録してください。

同時に大量のファイルを変更せず、カテゴリ単位で進めてください。

推奨順：
1. 鍵盤打楽器
2. 電子鍵盤
3. 小型打楽器
4. ギター・コントラバス
5. 和太鼓
6. アンプ
7. テーブル・汎用オブジェクト
8. ドラムセット3プリセット
9. 銅鑼、ウィンドチャイム、ハープ

各カテゴリごとにtypecheck、test、build、校正画面を確認してください。
```

## 実装後レビュー用の新規セッション

```text
docs/instrument-symbol-spec-final-v1.2.md を読み、現在の実装が仕様を満たしているか監査してください。

今回は原則としてコードを変更せず、レビューだけ行ってください。

以下を確認してください。

1. 非等方変形が残っていないか
2. visual バリエーション切替が寸法を変えていないか
3. projection アセットが平面配置へ混入していないか
4. ピアノのフル／セミと黒／白が分離されているか
5. ティンパニと4トムの固定配置
6. ドラムセットが一枚シンボルで、グループ解除不可か
7. ラベルが水平でフットプリントに混入していないか
8. 保存・再読込・ズーム・回転で寸法が変わらないか
9. 旧データ移行がユーザー変更値を保持するか
10. PNG／SVG／PDFまたは印刷出力で形が崩れないか
11. 認証・デプロイ等の無関係な変更が混ざっていないか
12. 全SVGに対応表、分類、寸法、使用状態があるか

重大度を Critical / High / Medium / Low に分け、
ファイル名と根拠を示して報告してください。
```
