# 舞台図面作成アプリ 楽器シンボル仕様書

## 1. 目的

本仕様は、舞台図面作成アプリにおける楽器シンボルの寸法、描画、操作、保存およびセット配置の基準を定める。

本アプリは製造図面や搬入設計を目的としない。実際の舞台上で、図面を参照しながら人が楽器を配置することを前提とする。

目標とする精度は次のとおりとする。

- 楽器同士の大小関係が自然である
- 舞台上の概略占有範囲が把握できる
- 同一縮尺上で明らかな違和感がない
- フル／セミ、大口径／小口径などの差が視覚的に分かる
- 数cm単位のスタンド脚や突起まで完全再現する必要はない
- 寸法値は「実寸の厳密な保証値」ではなく、図面用標準寸法として扱う

---

## 2. 基本設計方針

### 2.1 元SVGの扱い

既存の舞台仕込み図用SVGを、原則として視覚アセットに採用する。

ただし、SVGは形状を表す素材であり、SVG固有の `width`、`height`、`viewBox` を楽器の物理寸法として使用しない。

原本SVGは変更しない。

禁止事項：

- 原本SVGの `path` を直接編集する
- 原本SVGへ上書きする
- 色違いを寸法違いとして解釈する
- 元SVG全体を縦横別々に引き伸ばして寸法枠へ押し込む
- CSS、コンポーネント、カタログの複数箇所に補正値を分散させる

原本に補正が必要な場合は、次の優先順位とする。

1. アセットマッピングの誤りを修正
2. `contentBox` 等のメタデータでSVG内余白を補正
3. 専用の派生SVGを別ファイルとして作成
4. パラメトリック図形へ置換

### 2.2 寸法管理

寸法は `instrumentCatalog.ts` 等の単一カタログに集約する。

単位はmmとする。

```ts
type DimensionBasis =
  | "yamaha-reference"
  | "official-model-reference"
  | "nominal-size-plus-small-margin"
  | "representative-layout"
  | "user-defined";

type DimensionStatus =
  | "verified-reference"
  | "representative"
  | "user-defined";
```

### 2.3 物理領域と視覚領域

以下を分離する。

- **物理フットプリント**
  - 選択枠
  - 配置
  - スナップ
  - グループ外接範囲
  - 回転中心
- **視覚領域**
  - 元SVGまたは生成図形の描画
- **ラベル領域**
  - 楽器名、サイズ表記
  - 物理寸法や選択枠へ混入させない

### 2.4 縦横比

通常のSVGシンボルでは、非等方拡大縮小を禁止する。

```text
scaleX と scaleY を別値にしない
preserveAspectRatio を維持する
object-fit: contain 相当で描画する
```

元SVGの縦横比と採用寸法の比率が大きく異なる場合は、自動で歪ませない。アセット選定、専用派生SVG、パラメトリック生成のいずれかで解決する。

---


## 2.5 SVGバリエーションの分類

配布元の `A / B / C / D / W / B / G` 等の記号だけから、寸法差・用途差を推測してはならない。  
各SVGは実ファイルの形状と配布元名称を確認し、次のいずれかへ分類する。

### `visual`

色、塗り、線、描き込み等の視覚差。

- 切替時に寸法を変更しない
- 位置、回転、選択枠を変更しない
- アセットごとの余白差は `contentBox` で補正する
- ハープA／B／C、マリンバA／B、ビブラフォンA／B等は原則この分類とする

### `projection`

平面、置き、正面等の投影・用途差。

- 舞台平面図で通常配置できるかを `planEnabled` で管理する
- 正面図は原則 `planEnabled: false`
- 正面図を平面フットプリントへ押し込んで表示しない
- 凡例・注釈用途へ残す場合は `usage: "legend-only"` とする

### `preset`

サイズ、台数、構成、用途が異なるもの。

- 独立した寸法プリセットとして登録する
- フル／セミグランド、電子ピアノ73／88鍵、シンセ61／76／88鍵、ティンパニ各口径等が該当する
- コンガ単体／2本、ドラムセットのコンパクト／標準／大型も別プリセットとする

### バリエーション切替の原則

`visual` バリエーションを変更したとき、変更してよいのは `assetVariantId` のみとする。

変更してはならないもの：

- `widthMm`
- `depthMm`
- `xMm`
- `yMm`
- `rotationDeg`
- 選択枠
- 楽器プリセットID
- グループ構造

## 2.6 SVGアセットと楽器プリセットの分離

SVGファイルと図面用寸法プリセットを、同一データとして管理しない。

- **SymbolAsset**：どの絵を使うか
- **InstrumentPreset**：何の楽器として、どの寸法で置くか
- **GroupPreset**：複数オブジェクトをどの相対座標で置くか

同じSVGを複数の寸法プリセットで使用できる構造にする。  
同じ寸法プリセットから複数の視覚バリエーションを選択できる構造にする。

例：

```text
マリンバ
├─ 寸法プリセット：5オクターブ 2610×1030mm / 4オクターブ 2030×870mm
└─ 視覚バリエーション：5オクターブ A / B、4オクターブ A
```

```text
グランドピアノ
├─ 寸法プリセット：フル / セミ
└─ 視覚バリエーション：黒塗り / 白抜き
```

## 3. 共通操作仕様

### 3.1 回転・反転

- 回転：許可
- 左右反転：不要
- 上下反転：不要
- 配置直後の基準方向：
  - 画面上＝舞台奥
  - 画面下＝客席側

各シンボルは初期方向を統一する。

### 3.2 ラベル

- 楽器名ラベルは常に水平
- 楽器本体の回転に追従して文字を回転させない
- ラベルは原則として楽器内に表示
- 文字が少しはみ出すことは許容
- ラベルのはみ出しを理由にフットプリントや選択枠を拡大しない
- ティンパニは楽器名ではなくサイズ数字のみ表示

### 3.3 選択枠

- SVGの実描画境界ではなく、標準フットプリント矩形を使用
- 銅鑼、ハープ等の不定形シンボルも矩形選択でよい
- 回転後の画面上の外接矩形を元寸法として保存しない

保存値：

```ts
{
  widthMm: number;
  depthMm: number;
  rotationDeg: number;
}
```

### 3.4 サイズ変更

#### 共通原則

- 寸法変更は**数値入力のみ**とする。ドラッグによるリサイズハンドルはどのシンボルにも提供しない（要件定義書 FR-043）。
- すべてのプリセットの寸法は初期値であり、実際の備品・楽器に合わせて数値で変更できる（要件定義書 FR-044・6.2）。
- 楽器の種類によって「変更可／固定」を分けない。分けるのは**縦横を独立に変更できるか**だけとする。
- 変更後の寸法は `user-defined` として保持し、プリセット更新で上書きしない。

#### 縦横を独立に数値変更できる

- マルチパーカッション
- 小物置きテーブル
- ミニ小物置き
- 汎用矩形

#### 縦横比を維持して数値変更する

- ピアノ
- ハープ
- バスドラム
- ティンパニ（正円を維持）
- 銅鑼
- ドラムセット
- 汎用円（正円を維持）
- その他の楽器プリセット

縦横比維持のシンボルでは、幅を入力すると奥行が比率に従って追従し、その逆も同様とする。元SVGの非等方変形は生じない。

#### セット全体の寸法欄を持たないもの

- ティンパニ4台セット
- コンサートトム4台セット

グループ外接寸法は子要素と固定相対座標から自動算出するため、セット全体の寸法は直接入力しない。グループ解除後の各単体は上記の規則に従う。

## 4. セット物の共通仕様

### 4.1 グループプリセット

対象：

- ティンパニ4台セット
- コンサートトム4台セット

許可する操作：

- 移動
- 回転
- 複製
- 削除
- グループ解除

禁止する操作：

- セット全体のドラッグリサイズ
- セット全体の外接寸法の直接入力
- セット全体の縦横別伸縮
- 配置後の自動整列
- 保存時に子要素の座標を再計算する処理

単体オブジェクトを固定相対座標で並べたグループプリセットとして実装する。  
グループ外接寸法は子要素から自動算出する。

### 4.2 一枚シンボルのセット

対象：

- ドラムセット（コンパクト／標準／大型）

許可する操作：

- 移動
- 回転
- 複製
- 削除
- 縦横比を維持した数値での寸法変更

禁止する操作：

- ドラッグリサイズ
- 縦横別伸縮
- グループ解除
- 左右反転

ドラムセットは各プリセットを一枚のシンボルとして扱う。  
ティンパニ・4トムのグループ仕様を適用しない。

# 5. 楽器別仕様

## 5.1 グランドピアノ

### プリセット

| ID | 表示名 | 基準 | 幅 | 奥行 |
|---|---|---|---:|---:|
| `grand-piano-full` | フルコンサートグランド | YAMAHA CFX | 1600mm | 2750mm |
| `grand-piano-semi` | セミグランド | YAMAHA CF6級 | 1540mm | 2120mm |

### 視覚仕様

- フルとセミは別の輪郭を使用する
- 黒塗り／白抜きを選択可能にする
- 色違いSVGをフル／セミの差として使用しない
- SVGファイル名の A / B / W / B 等を、寸法分類だと推測しない
- 現在のアセットマッピングを先に監査する
- 配布素材に適切なフル／セミ輪郭がある場合は、それぞれ採用
- 適切な輪郭がない場合は、原本を保持したまま専用派生SVGを作る

派生SVGを作る場合：

- 鍵盤側の幅を不自然に変えない
- 胴体後方の長さの違いでフル／セミを表現する
- 元SVG全体の縦方向単純圧縮は禁止

```ts
type PianoVariant = {
  sizeVariant: "full" | "semi";
  colorVariant: "black" | "outline";
};
```

## 5.2 コンサートバスドラム

### 標準

- 36 × 22インチ
- スタンドは考慮しない
- 図面上：
  - 縦＝36インチ
  - 横＝22インチ

| 項目 | 寸法 |
|---|---:|
| 縦 | 914.4mm |
| 横 | 558.8mm |

実装上は `914 × 559mm` または元値を小数で保持する。

### 描画

- 既存SVGを914×559mmへ非等方変形しない
- 元SVGの縦横比が合わない場合は、寸法からパラメトリックに生成する
- 本体のみ描画し、スタンドはフットプリントに含めない

## 5.3 ティンパニ

### 単体プリセット

元の4台セットSVGは使用しない。

装飾なしの円形オブジェクトとして生成する。

| 公称サイズ | 図面用円直径 | 表示 |
|---|---:|---|
| 23インチ | 750mm | `23` |
| 26インチ | 800mm | `26` |
| 29インチ | 900mm | `29` |
| 32インチ | 950mm | `32` |

- 表示は数字のみ
- 数字は常に水平
- 単体で配置可能
- 円の形状をSVGに依存させない

### 4台セット

- 上記4種の単体円から構成
- 並び方は配布元のティンパニ4台セットSVGを参照
- SVGから使用するのは配置関係のみ
- セット間隔は固定
- 2×2の格子状にはしない
- 配置後のセット全体リサイズは禁止
- 単体4台としてグループ解除可能

## 5.4 コンサートトム4台セット

### 構成

大きい方から：

1. 16インチ
2. 14インチ
3. 12インチ
4. 10インチ

### 配置

- 左から右へ大きい順
- 緩い弧状
- 直線配置にしない
- 2×2の格子状にしない
- スタンドの寸法は考慮しない
- 各トムは円形で表す
- セット間隔は固定
- 一つの巨大SVGではなく、4つの子オブジェクトから構成する

各円の図面用直径は、公称径にごく小さな余白を加えた値としてカタログに集約する。補正値をコンポーネント内へ直接記述しない。

## 5.8 ハープ

### 標準

- 楽器プリセット：グランドハープ
- 基準：青山ハープ47弦フルコンサートタイプ
- 図面用標準フットプリント：**1050×700mm**
- 寸法区分：`representative-layout`

幅・奥行は、特定製品の厳密な公式平面外形ではなく、47弦フルコンサートハープを舞台平面図へ配置するための代表値として扱う。

### SVGバリエーション

配布元のハープA／B／Cを、同一寸法の `visual` バリエーションとして選択可能にする。

- A／B／Cの切替で寸法を変更しない
- 位置、回転、選択枠を変更しない
- 各SVGの余白差はアセット別 `contentBox` で補正する
- A／B／Cをサイズ分類として扱わない
- 配置時および配置後のプロパティ欄で選択可能にする
- 小さなプレビュー付き選択UIを推奨する

表示名：

```text
グランドハープ（青山47弦フルコンサート基準）
```

## 5.12 全シンボル寸法マスター

### 5.12.1 本節の位置づけ

本節は、配布元の楽器・音響機材SVGを `instrumentCatalog.ts` へ登録する際の**初期寸法マスター**とする。

- 表記は原則として **幅×奥行（mm）**
- 円形のものは **直径（mm）**
- 厳密な製造寸法ではなく、舞台平面図用の標準フットプリント
- メーカー公式寸法を採用できるものは公式・代表機種を基準にする
- 機種差や組み方の差が大きいものは、代表配置寸法を採用する
- A／B／C、W／B、G等の記号は、原則として視覚・塗り・向きのバリエーションであり、寸法分類だと推測しない
- 同一楽器のSVGバリエーションには、原則として同じ寸法プリセットを割り当てる
- 寸法と視覚アセットの対応は独立させる

寸法区分：

| 区分 | 意味 |
|---|---|
| `yamaha-reference` | YAMAHAの代表機種・公式仕様を基準 |
| `official-model-reference` | 指定メーカーの代表機種を基準 |
| `nominal-size-plus-small-margin` | 公称径・本体外形に小さな図面用余白を追加 |
| `representative-layout` | 構成・スタンド・置き方を含む図面用代表値 |
| `user-defined` | ユーザーが変更した寸法 |

---

### 5.12.2 弦楽器・ギター類

「正面」SVGも保持できるが、平面図上の初期フットプリントは対応する「置き」状態と同じ値を使用する。  
正面SVGの見た目の縦横比を、フットプリントへ合わせて歪ませてはならない。

| プリセットID | 配布元SVG | 図面用寸法 | 寸法区分 | 備考 |
|---|---|---:|---|---|
| `acoustic-guitar-body` | アコースティックギターA | 1050×450 | `representative-layout` | 楽器本体を横置きした場合 |
| `acoustic-guitar-stand` | A置き／A正面 | 500×400 | `representative-layout` | ギタースタンド置き |

# 7. 保存・互換性

## 7.1 保存原則

- 現行のmm座標系を維持する
- 保存時に画面px、ズーム倍率、回転後外接矩形を物理寸法へ混入させない
- ラベルは物理フットプリントに含めない
- `visual` バリエーション切替では `assetVariantId` のみを変更する
- ティンパニ・4トムは子要素の相対座標を保存する
- ドラムセットは一枚シンボルとして保存する
- ユーザー変更寸法は `user-defined` として保持する
- プリセット更新でユーザー変更寸法を上書きしない

## 7.2 スキーマ移行

現行スキーマを調査し、新形式へ移行する場合はスキーマバージョンを上げる。

移行処理は次を明示する。

- 旧プリセットID → 新プリセットID
- 旧SVGアセットID → 新 `assetVariantId`
- 誤割当されたフル／セミピアノの補正
- 旧ティンパニ4台セット → 単体4台グループ
- 旧トムセット → 16／14／12／10の弧状グループ
- 旧ドラムセット → コンパクト／標準／大型のどれへ対応するか
- 旧保存値に `scaleX / scaleY` がある場合の扱い

原則：

- 利用者が個別変更した寸法は保持する
- 旧プリセット初期値のままの項目だけ、新標準値へ移行できる
- 移行不能な項目は黙って推測せず、警告または旧レンダラーへフォールバックする
- 移行処理には単体テストを用意する

---

# 8. 実装時の禁止事項

1. 元SVG全体を `scaleX !== scaleY` で変形する
2. フルとセミに同一輪郭の色違いだけを割り当てる
3. ティンパニ4台セットSVGをそのまま寸法基準にする
4. ティンパニセットや4トムを2×2へ自動整列する
5. リサイズハンドルを付ける（全シンボル共通。寸法変更は数値入力のみ）
6. ラベルを外接寸法へ含める
7. 回転後の外接矩形を保存寸法として使用する
8. 補正値をCSSやコンポーネント内へ散在させる
9. 元SVGの `path` を場当たり的に編集する
10. 未確認の楽器寸法を推測で登録する
11. 現行シンボル機構全体を一括削除してから再実装する
12. シンボル作業と無関係な認証・デプロイ変更を同じ差分へ混在させる
13. 正面図SVGを平面図用アセットとして自動採用する
14. `visual` バリエーション切替時に寸法や選択枠を変更する
15. ドラムセットへグループ解除操作を付ける
16. 実ファイルとアセットIDの対応表を作らず、一括で自動割当する

# 9. 実装順序

1. 作業ブランチ作成・未コミット変更の確認
2. 原本SVGと現行SVGの差分・ハッシュ・ファイル名を監査
3. 全SVGのアセット対応表を作成
4. 各SVGを `visual / projection / preset` に分類
5. `SymbolAsset` と `InstrumentPreset` を分離
6. 現行保存形式と移行対象を調査
7. ピアノのフル／セミ／黒／白を修正
8. 通常SVGの非等方変形を防止
9. バスドラム36×22を実装
10. ティンパニ単体4種と4台セットを実装
11. コンサートトム4台を緩い弧状に実装
12. 銅鑼36インチを実装
13. ウィンドチャイム35音を実装
14. ドラムセット3プリセットを実装
15. ハープA／B／Cの選択UIを実装
16. マリンバ等のA／B選択UIを順次実装
17. マルチパーカッション、小物置き、汎用図形を実装
18. その他の全インベントリを寸法マスターへ登録
19. 保存スキーマ移行を実装
20. 単体テスト、型検査、ビルド
21. 校正用舞台の視覚回帰確認
22. PNG／SVG／PDFまたは印刷出力を確認
23. シンボル作業だけのPRとしてレビュー

各段階で結果を報告し、問題がある状態で次工程へ進まない。

# 10. 受入条件

## 10.1 形状

- ピアノのフル／セミが見た目でも区別できる
- ピアノ、バスドラムの縦横比が崩れていない
- 通常SVGに非等方変形がない
- ティンパニ単体が正円である
- ティンパニ4台セットが配布元SVGを参照した弧状配置になっている
- コンサートトムが16・14・12・10の順で緩い弧状になっている

## 10.2 操作

- ラベルが常に水平
- どのシンボルにもリサイズハンドルが表示されない
- セット物の外接寸法を直接入力できない
- 左右反転操作が存在しない
- 楽器プリセットの寸法を数値で変更でき、縦横比維持のものは片方の入力へもう片方が追従する
- テーブル、マルチ、汎用矩形は縦横を独立に数値変更できる
- 選択枠が物理フットプリントに一致する

## 10.3 保存

- 回転、ズーム、保存、再読込後も寸法比率が変わらない
- ティンパニおよび4トムの子座標が保持される
- ユーザー変更寸法がプリセット更新で失われない
- 旧プロジェクトが読み込める

## 10.4 視覚回帰

同一校正舞台上に次を並べた固定検証図面を作る。

- フルグランド黒／白
- セミグランド黒／白
- バスドラム36×22
- 銅鑼36インチ
- ウィンドチャイム35音
- ティンパニ23／26／29／32
- ティンパニ4台セット
- コンサートトム4台セット
- ドラムセット3種
- ハープ
- マルチパーカッション
- 小物置きテーブル標準／ミニ
- 汎用矩形／汎用円
- マリンバ／ビブラフォン／シロフォン／グロッケン／チャイム
- アップライトピアノ／チェレスタ
- 電子ピアノ73・88鍵／シンセ61・76・88鍵
- スネア／サスペンデッドシンバル／クラッシュシンバル
- コンガ単体・2本／ボンゴ
- ギター類／コントラバス
- 和太鼓各種
- 楽器アンプA～H

ズーム50％、100％、200％でスクリーンショットを取得し、形状と比率を比較する。
全インベントリについて、未登録・重複ID・寸法未設定がないことも自動検査する。


## 10.5 バリエーション

- ハープA／B／Cを選択できる
- マリンバ、ビブラフォン、シロフォン、グロッケン、チャイムのA／Bを選択できる
- `visual` バリエーション切替前後で寸法、位置、回転、選択枠が不変
- 電子ピアノ・シンセでは鍵盤数プリセットとA／B見た目が独立している
- 正面図アセットを通常の平面配置一覧へ表示しない
- 未分類アセットが残っていない

## 10.6 出力

- PNG出力後も縦横比が維持される
- SVG出力後も縦横比が維持される
- PDFまたは印刷出力後も縦横比が維持される
- 出力後もラベルが水平
- SVGの線・端部がクリッピングされない
- 出力処理で `width / height` を再適用して非等方変形しない

## 10.7 移行

- 旧プロジェクトの主要サンプルを読み込める
- 旧ピアノの誤マッピングが仕様どおり補正される
- 旧ティンパニセットが単体4台へ変換される
- ユーザー変更寸法が保持される
- 変換不能項目は警告され、黙って別楽器へ置換されない

# 11. Codexでの運用

実装は**新しいCodexセッション**で行う。  
本仕様書はリポジトリ内の次の位置に置かれている。

```text
docs/instrument-symbol-spec-final-v1.2.md
```

別ファイル `docs/codex-instrument-symbol-kickoff.md` の指示を、新規セッションの最初のメッセージとして使用する。

原則：

- 最初のターンでは調査と計画のみ
- 承認前にコードを変更しない
- 全楽器を一括実装しない
- 仕様書と現行実装が衝突する場合は、正常な既存機能を保護しながら仕様に合わせる
- 認証・デプロイ等の無関係な変更を同じ差分へ含めない
- 実装後のレビューは、可能なら別の新規Codexセッションで行う

# 13. 実装時に残る確認事項

全シンボルの初期寸法値と操作方針は本仕様で定義済みとする。  
残る確認事項は、主にアセットの実態と視覚校正である。

1. 配布元SVGとリポジトリ内実ファイルの正確な対応表
2. 各SVGの `visual / projection / preset` 分類
3. グランドピアノ各SVGの輪郭・色・図案差
4. 各SVGの `contentBox`
5. ティンパニ4台セットの固定相対座標
6. コンサートトム4台セットの固定相対座標
7. 和太鼓各SVGの台・向き・図案差
8. アンプA～Hと代表寸法クラスの対応
9. 正面図・置き図・平面図の用途分類
10. 既存保存スキーマから新形式への具体的移行表
11. 校正用舞台上で見た場合の代表寸法微調整

これらを理由に元SVGを非等方変形してはならない。  
必要な調整は、アセット対応表、`contentBox`、寸法カタログ、固定グループ座標へ集約する。

# 14. ライセンス・出典管理

配布SVGと派生SVGの出所を追跡できるよう、リポジトリへ次を追加する。

```text
THIRD_PARTY_NOTICES.md
```

最低限記録するもの：

- 配布元名称
- 配布元ページ
- 原本取得日
- 使用した原本ファイル一覧
- 原本ハッシュ
- 改変の有無
- 派生SVGと元SVGの対応
- 寸法値の基準種別

原本フォルダと派生フォルダを分離し、派生SVGを原本と誤認しない構成にする。
