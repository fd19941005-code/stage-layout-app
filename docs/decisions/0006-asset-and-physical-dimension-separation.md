# ADR-0006: 見た目assetと物理寸法カタログを分離する

- 状態: 採用
- 対象: 楽器シンボル、プリセット、保存互換性

## 背景

楽器シンボルのSVGは見た目・向き・バリエーションを表すが、SVGのviewBoxや描画比率が現実の寸法を保証するわけではない。assetを差し替えたときに、既存Projectの実寸が変わると図面の意味が壊れる。

## 決定

シンボルasset、楽器カタログの標準寸法、プリセット生成を分離する。新規配置ではカタログの標準寸法を使い、既存Projectの明示的なmm寸法は保存データとして尊重する。instrument IDや寸法構造を変更するときは`src/core/project.ts`のマイグレーションで旧データを読めるようにする。

## 理由と結果

- 見た目の改善と物理寸法の変更を別々にレビューできる。
- 既存ユーザーの配置をasset更新で意図せず変えない。
- 追加楽器では、外観が用意できても寸法根拠がない場合は不確実性を明示する。
- カタログ変更には、保存互換性と寸法テストを伴わせる必要がある。

## 根拠

`src/core/presets.ts`、`src/core/instrumentCatalog.ts`、`src/core/symbolAssets.ts`、`src/types/project.ts`、`src/core/project.ts`、楽器シンボル仕様書と実装履歴。
