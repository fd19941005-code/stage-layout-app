# ドメインモデルと不変条件

この文書は、舞台図面アプリ固有の概念を説明する。正式な要求番号と受入条件は `要件定義書_v1.0.md` がSource of Truthであり、この文書は実装時の意味と危険な前提を補足する。

## 基本概念

- **Project**: 背景、校正、ビュー、レイヤー、配置物、ガイド、壁、舞台前、ステージテンプレート、出力設定を含む保存単位。
- **SceneObject**: 楽器、椅子、譜面台、台、注釈など、平面図上の要素。実寸の位置・寸法・角度を持つ。
- **背景**: 画像またはPDFページを埋め込んだ参照図。背景の自然px情報と切り抜き・90度回転を持つが、配置物の正本ではない。
- **Calibration**: 背景上のsource px 2点と実距離mmから、背景と舞台座標を対応付ける情報。現実装は1つの `mmPerPixel` を使う。
- **ViewState**: ズームとパンなど画面表示だけの状態。`Project.view`としてJSONには含まれるが、実寸データや配置座標を変更せず、viewだけの変更ではUndo履歴や自動保存を起動しない。
- **Layer**: 背景、オブジェクト、注釈などの表示・ロック単位。
- **Guide / Wall / StageFront**: ガイド線、壁のmm頂点列、舞台前の予約領域。いずれも表示・配置判断のためのProjectデータであり、SVGの座標を正本にしない。
- **Stage template**: 背景なしで舞台の実寸グリッドやプリセット寸法を準備する機能。画像校正済みの背景とは別の準備経路である。
- **Riser**: 高さを持つ台。`onRiserId`による配置物との関連付けがあり、2Dでは平面位置、3Dでは段高へ派生する。
- **Asset / preset**: SVG等の見た目と、カタログ上の標準寸法を分離したもの。見た目のassetのpx寸法を実寸の正本にしない。
- **Preview**: 配置・ドラッグ・ダイアログ操作の途中結果。確定前は保存対象の正本ではない。

## 実寸と座標の契約

配置物の正本は次のmmフィールドである。

```text
xMm, yMm, widthMm, depthMm, heightMm, rotationDeg
```

- `widthMm` と `depthMm` は、物体固有の未回転寸法である。
- `rotationDeg` は描画変換・向きを表す。回転に合わせてwidth/depthを交換しない。
- SVGの描画座標・bounding box、ポインターの一時px、Three.jsのmeshやcameraは派生値であり、保存しない。例外として`ViewState.panX/panY`は表示オフセットとしてProject JSONに含まれるが、実寸座標ではない。
- 画面ズーム・パンは表示だけを変える。
- 背景画像のsource px、校正済みmm、画面pxの変換は `src/core/transform.ts` に集約する。

画面のY軸はSVG／画面座標として下向きが正である。弦楽器テンプレートでは舞台奥方向を画面上、すなわちY負方向として固定している。このテンプレート固有の座標前提を、一般の舞台前後の意味へ暗黙に拡張しない。

## 保存と互換性

保存JSONにはschemaVersionを持たせる。現在の型定義上のバージョンは `src/types/project.ts` の `SCHEMA_VERSION` を確認する。保存形式を変更する場合は、バージョン更新と `src/core/project.ts` のマイグレーションを同時に行う。

復元時は必要な既知フィールドだけを検証し、未知フィールドは無視する。入力にない新フィールドには安全な既定値を与える。既存ユーザーの寸法や配置を、見た目assetの更新だけで上書きしない。

自動保存の正規入口は`AutosaveService`であり、Web版はIndexedDBを優先し、失敗時にlocalStorageへ退避する。保存要求は直列化され、IndexedDBとlocalStorageの両方に有効なデータがある場合は`updatedAt`が新しい方を復元する。`src/core/storage.ts`は旧import互換の再exportであり、新しいドメインロジックの保存先ではない。

## 配置生成の意味

行列、プルト弧、椅子円弧列、山台、弦セクションテンプレートは、入力値から通常の `SceneObject` を生成する純粋計算である。ライブプレビューは同じ計算を使い、確定時にだけ生成物をProjectへ追加する。

弦楽器テンプレートはファイル名に`12`を含むが、現行コードでは8／10／12／14／16型と、standard／standard-swap／antiphonal／antiphonal-swapの4バリアントを扱う。人数を任意入力する一般編成エンジンではなく、固定の編成データとアンカーを選ぶ機能である。旧仕様書の「12型のみ」や動的人数入力の記述は現在仕様ではない。

## 変更時に特に危険なこと

- UIで一時的に扱うpx座標をProject型へ追加しない。
- 回転済みの見た目を理由にwidth/depthを入れ替えない。
- reducerを迂回して配列を直接変更しない。履歴・自動保存・Undo/Redoの境界が壊れる。
- プレビュー生成物を確定前に保存・hit testの正本へ混ぜない。
- `onRiserId`を単なる表示ラベルとして扱わない。3Dの段高派生に使われる。
- 校正、背景回転、切り抜き、出力縮尺を一つの画面ズームの値で代用しない。
