# 操作高速化 実装依頼プロンプト

別のAI（Codex / Claude Code / その他のコーディングエージェント）へ実装を依頼するための本文集。
`docs/操作高速化_仕様書_v1.0.md` とセットで使う。仕様書はリポジトリ内にあるので、プロンプト側では**場所を指すだけ**にして本文へ仕様を写経しない（二重管理を避けるため）。

使い方: 下の `~~~` で囲まれた部分をそのままコピーして渡す。Phase A → B → C の順に、1フェーズ1依頼で出す。まとめて渡すと変更範囲が大きくなり、レビューとUndo単位の検証が難しくなる。

---

## 共通の前提（依頼前に確認すること）

- 現在のブランチは作業中で、未コミットの変更が多数ある。**依頼前に `git status` を確認し、必要なら先にコミットまたはstashしておく**。依頼先AIには「既存の未コミット変更を巻き戻すな」と伝えているが、作業前に区切りを付けておくほど事故は減る。
- 依頼先が別マシン・別環境の場合、`npm ci` が通ることを先に確認する。
- 完了後は `docs/操作高速化_仕様書_v1.0.md` の受入条件（AC-KEY-001〜、AC-PTR-001〜、AC-DSC-001〜）を自分で1つずつ確認する。AIの自己申告だけで完了としない。

## 依頼先AIが仕様から外れやすい点（レビュー時に見る場所）

過去のこの種の依頼で起きやすい逸脱を挙げる。受け取ったコードはここを重点的に確認する。

| 見る場所 | 起きやすい逸脱 |
|---|---|
| `src/core/keyboardShortcuts.ts` | 純粋関数へ集約せず、`App.tsx` や各コンポーネントに `event.key === "v"` を直接書く |
| 除外条件 | IME変換中（`isComposing`）の判定が漏れ、日本語入力でモードが切り替わる |
| 除外条件 | プレビューセッション中・ダイアログ表示中の除外が漏れ、円弧配置の最中にモードが変わる |
| `blocksCanvasShortcut` | フォーカス復帰ではなく、この関数の判定を緩めて「解決」してしまう（誤爆が増える） |
| Undo履歴 | 回転や複製がドラッグ中に何度も履歴へ積まれる |
| 新規Action | 既存Actionで足りるのに `NUDGE_*` 風の新Actionを増やす |
| 保存形式 | 端末ローカル設定のつもりが `project.displaySettings` へ入り、JSONの内容が変わる |
| 既存テスト | 期待値を書き換えて通す |
| タッチ | キーボードでしか到達できない操作が増え、iPadで使えない |
