# 1. 背景・目的

吹奏楽・管弦楽の舞台配置では、複数列の椅子を指揮台を基準とした円弧上へ配置する作業が頻繁に発生する。現状の手動配置および既存のプルト弧状配置では、列ごとに異なる椅子数を持つ吹奏楽型の座席列を短時間で作成しにくい。

本機能では、選択した指揮台を基準として、列ごとの椅子数、円弧の方向、円弧の左右端、1列目までの距離、列間隔を指定し、複数列の椅子を同心円弧上へ一括生成する。

## 1.1 最重要原則

- 配置計算の正本はすべてmmとする。
- プレビュー用の画面pxをプロジェクトへ保存しない。
- 生成確定時に通常の椅子オブジェクトへ変換する。
- 配置設定そのものは保存モデルへ追加しない。
- 一括生成は1回のActionおよび1回のUndo単位とする。
- 既存のプルト弧状配置を変更・破壊しない。
- 標準椅子の円形化は実装済みの前提とし、本機能では椅子シンボル、SVG、プリセット寸法、ラベル表示を変更しない。
- 実装時は現在の作業ツリーを正本とし、椅子円形化を含む既存変更を巻き戻さない。

# 2. 適用範囲

## 2.1 本機能に含むもの

- 指揮台を基準とする多列円弧配置
- 列ごとの椅子数指定
- 列の追加・削除
- 1列目までの距離指定
- 2列目以降の列間隔指定
- 円弧の方向指定
- 左右対称な円弧端の指定
- 全列の両端方向揃え
- 確定前のリアルタイムプレビュー
- 椅子同士の重なり警告
- 既存オブジェクトとの重なり警告
- 有効舞台範囲が定義済みの場合の舞台外警告
- 一括生成後の個別編集
- 一括Undo/Redo

## 2.2 本機能に含めないもの

- 後列の千鳥配置
- 列ごとの自動横ずらし
- 中央通路の自動確保
- パート・楽器別の自動編成配置
- 譜面台の同時自動配置
- 生成後の円弧パラメーター再編集
- 椅子列をパラメトリックオブジェクトとして保存する機能
- 椅子以外の任意オブジェクトの多列円弧配置
- 椅子の向き・回転制御
- 椅子シンボルの円形化、再設計、SVG差し替え
- 標準椅子プリセットの寸法・名称・ラベル仕様の変更

---

## 2.3 実装済み前提

標準椅子 `chair` の円形化は本機能の着手前に完了している。したがって、本機能の実装者は次を前提とする。

- ライブラリから単体配置した標準椅子が円形で描画される。
- PNG/PDF出力、保存・復元、3D表示等における椅子の扱いは既存実装を正本とする。
- 多列円弧配置で生成する椅子も、`createPresetObject("chair", ...)` 等の既存生成経路を通し、単体配置と同じ表示関連フィールドを持たせる。
- 円弧配置機能内に独自の円描画、専用SVG、専用シンボルIDを追加しない。
- 現在の作業ツリーにある椅子円形化の変更を削除、置換、巻き戻ししない。
- アップロード済み資料と現在のコードが異なる場合は、現在の作業ツリーを優先する。

# 3. 用語

| 用語 | 定義 |
|---|---|
| 基準指揮台 | 本機能の起動時に選択されている `type: "podium"` のSceneObject。 |
| 円弧中心 | 基準指揮台の中心座標 `xMm / yMm`。 |

| プレビュー椅子 | 確定前に表示する一時的な椅子。ProjectおよびUndo履歴には追加しない。 |

# 4. ユースケース

## UC-064-01 多列椅子円弧配置

1. 利用者が指揮台を1台選択する。
2. 「椅子を多列円弧配置」を実行する。
3. アプリが指揮台を円弧中心としてプレビューを表示する。
4. 利用者が座席列を置く方向を指定する。
5. 利用者が円弧の左右端を調整する。
6. 利用者が各列の椅子数を入力する。
7. 利用者が距離・列間隔を必要に応じて変更する。
8. アプリが結果と警告をリアルタイム表示する。
9. 利用者が「配置する」を押す。
10. アプリが全椅子を通常のSceneObjectとして1回のActionで追加する。
11. 生成された全椅子を選択状態にする。
12. 利用者は必要な椅子だけを個別に移動・削除できる。

## 6.3 キャンバス操作

### 方向指定

- 「方向を指定」を押した後、キャンバス上の任意点を1回クリックまたはタップする。
- 指揮台中心から指定点へのベクトルを中心方向とする。
- 指揮台中心と指定点が同一または極端に近い場合は入力を拒否する。
- 指定後も方向ハンドルをドラッグして変更できる。

### 円弧端指定

- 1列目の左端・右端にハンドルを表示する。
- ハンドルは1列目の半径上だけを移動可能とする。
- 左右対称を固定し、片側を動かすと反対側を中心方向に対して鏡映する。
- 円弧角の数値入力とハンドル位置を双方向同期する。

### タッチ操作

- ハンドルの実タップ領域は44px以上とする。
- ハンドル操作中はブラウザのスクロールおよびページズームと競合させない。
- プレビュー操作にはPointer Eventsを使用する。

# 7. 配置計算仕様

## 7.1 座標系

- `SceneObject.xMm / yMm` はオブジェクト中心座標である。
- 円弧中心 `C` は基準指揮台の中心座標とする。
- 中心方向の単位ベクトルを `u` とする。
- `u` に直交する左方向単位ベクトルを `v` とする。
- 画面のY軸方向に依存せず、ベクトル演算だけで計算する。

## 7.2 指揮台の方向支持距離

基準指揮台が回転している場合も、中心方向上の外形端を正しく求める。

指揮台のローカル幅方向・奥行き方向の単位ベクトルをそれぞれ `eW`、`eD` とし、幅・奥行きを `W`、`D` とする。

中心方向 `u` に対する指揮台中心から外形端までの距離 `podiumExtentMm` は次式とする。

```text
podiumExtentMm = |dot(u, eW)| × W / 2 + |dot(u, eD)| × D / 2
```

この計算はUIコンポーネントではなく、`core`配下の純粋関数へ実装する。

## 7.3 椅子半径

標準椅子プリセット `chair` は円形化済みである。本機能はその既存実装を参照し、円形化処理やシンボル変更を追加しない。

配置距離および重なり判定に用いる椅子半径は、現在の `chair` プリセットの実寸から次式で取得する。

```text
chairRadiusMm = max(widthMm, depthMm) / 2
```

標準 `chair` が450×450mmの場合、椅子半径は225mmとなる。

- 半径をハードコードせず、`chairTemplate.widthMm / depthMm` から取得する。
- 本機能の都合で `chair` を450×450mmへ上書きしない。
- 既存実装で寸法が変更されている場合は、現在のプリセット値を正本とする。
- 円形表示済みの標準椅子は幅と奥行きが等しいことを前提とする。差がある場合は、描画実装に合わせて半径を決め、テストで明示する。

## 7.4 1列目半径

1列目の円弧半径 `R1` は次式とする。

```text
R1 = podiumExtentMm + firstGapMm + chairRadiusMm
```

既定値では、指揮台が900×900mmで中心方向が辺に垂直、椅子が450×450mmの場合、

```text
R1 = 450 + 1820 + 225 = 2495mm
```

となる。

### 距離定義上の注意

- 1820mmは中心方向上で測る。
- 指揮台と各端席との最短外形距離を1820mmへ揃える仕様ではない。
- 全椅子を同一円弧へ置くことを優先する。

## 7.5 各列の半径

0始まりの列番号を `rowIndex` とした場合、各列の半径 `Rrow` は次式とする。

```text
Rrow = R1 + rowIndex × rowGapMm
```

既定の `rowGapMm` は910mmとする。

## 7.6 円弧端

中心方向角を `centerAngle`、円弧半角を `halfSpan` とする。

```text
startAngle = centerAngle - halfSpan
endAngle   = centerAngle + halfSpan
```

全列で同じ `startAngle / endAngle` を使用する。これにより、各列の左右端は円弧中心から見て同じ放射方向上へ揃う。

## 7.7 列内の椅子配置

列内の椅子数を `N` とする。

### N = 1

中央線上へ1脚配置する。

```text
angle(0) = centerAngle
```

### N >= 2

左右端を含め、等角度間隔で配置する。

```text
angle(i) = startAngle + (endAngle - startAngle) × i / (N - 1)
```

```text
xMm(i) = C.xMm + cos(angle(i)) × Rrow
yMm(i) = C.yMm + sin(angle(i)) × Rrow
```

- 奇数脚では中央の椅子が `centerAngle` 上に一致する。
- 偶数脚では中央線の左右へ同数ずつ配置される。
- 偶数脚の中央へ追加の椅子は置かない。
- `rotationDeg` は既存の `chair` テンプレート値を保持する。円弧方向に応じた回転計算は行わない。

## 7.8 優先順位

配置条件が相互に影響する場合は次の順に優先する。

1. 指揮台から1列目までの空き距離
2. 列間隔
3. 全列の左右端方向揃え
4. 各列の指定脚数
5. 各列内での等角度配置
6. 結果として生じる列ごとの椅子間隔

列ごとの椅子間隔を同一にするための自動半径変更は行わない。

# 9. 警告仕様

## 9.1 生成椅子同士の重なり

円形椅子A・Bについて、中心間距離が半径合計未満の場合に重なりとする。

```text
distance(A, B) < radiusA + radiusB
```

標準椅子同士では、中心間距離が450mm未満の場合に重なりとなる。

警告例：

> 1列目の椅子同士が重なっています。円弧を広げるか、椅子数を減らしてください。

## 9.2 既存オブジェクトとの重なり

- 既存の共通重複判定ロジックがある場合はそれを利用する。
- 初期実装では、生成椅子の円外形と既存オブジェクトの回転後外接矩形との交差判定を許容する。
- 警告対象の既存オブジェクトIDと生成椅子の列・番号を内部で識別可能にする。
- 警告があっても「配置する」は有効とする。

警告例：

> 2列目の椅子3脚が既存オブジェクトと重なっています。

## 9.3 舞台外警告

- 明示的な有効舞台範囲が設定されている場合のみ判定する。
- 背景画像の外周を舞台境界とみなしてはならない。
- 舞台範囲が未設定の場合は判定しない。
- 警告があっても配置を許可する。

## 9.4 警告表示方法

- 問題のあるプレビュー椅子を色だけでなく輪郭・アイコン等でも識別できるようにする。
- ダイアログ内へ警告件数と内容を文章で表示する。
- 警告と入力エラーを区別する。

# 10. 入力検証・エラー処理

## 10.1 入力エラー

次の場合は配置を確定できない。

- 指揮台が選択されていない
- 複数オブジェクトが選択されている
- 選択物が指揮台ではない
- 校正されていない
- 配置先レイヤーが非表示またはロック中
- 列数が0
- 椅子数が範囲外
- 距離が0以下または非有限値
- 円弧角が5度未満または180度超
- 中心方向ベクトルを確定できない
- 計算結果にNaNまたはInfinityが含まれる

## 10.2 正規化

- 椅子数・列数は整数化する。
- 距離は正の有限値に限定する。
- 角度は共通の `normalizeDeg` 方針へ従う。
- 不正値を黙って大幅補正せず、原則として入力欄へエラーを表示する。
- JSON保存モデルには新規設定を追加しないため、マイグレーションは不要とする。

# 11. 確定処理

## 11.1 Action

新規Actionを追加する。

```ts
| {
    type: "ADD_CHAIR_ARC_ROWS";
    options: ChairArcRowsOptions;
  }
```

推奨型：

```ts
export interface ChairArcRowSpec {
  chairCount: number;
}

export interface ChairArcRowsOptions {
  podiumId: string;
  directionDeg: number;
  halfSpanDeg: number;
  firstGapMm: number;
  rowGapMm: number;
  rows: ChairArcRowSpec[];
  layerId: string;
}
```

方向は点座標ではなく、確定時点ではmm座標系の角度または単位ベクトルへ正規化してActionへ渡す。

## 11.2 Reducer処理

1. `podiumId` から指揮台を再取得する。
2. 指揮台の存在、種類、可視性、レイヤー状態を再検証する。
3. 配置先レイヤーの可視性・ロック状態を再検証する。
4. `chair` プリセットからテンプレートを生成する。
5. `createChairArcRowObjects` で全椅子を生成する。
6. 全椅子をProjectへ一括追加する。
7. `commitProject` を1回だけ呼ぶ。
8. 生成した全IDを選択状態へ設定する。

## 11.3 生成オブジェクト

- `type`: `chair`
- `shape`: 既存の標準 `chair` プリセットから継承し、この機能では上書きしない
- `presetId / assetVariantId / style` 等の表示関連フィールド: 既存の標準 `chair` テンプレートから継承し、この機能では変更しない
- `widthMm / depthMm / heightMm`: 現在の標準 `chair` プリセットを継承
- `xMm / yMm`: 円弧計算結果
- `rotationDeg`: テンプレート既定値を継承。円弧角度から算出しない
- `layerId`: 配置先レイヤー
- `locked`: false
- `groupId`: null
- `visible`: true
- `zIndex`: 既存最大値以降で重複しない連番
- `label`: 既定の椅子名を維持する。列番号・席番号を表示名へ強制付加しない。

## 11.4 ID

- 既存の `generateId` を使用する。
- 例：`chair-arc-r1-c1-*`
- ID形式は表示仕様にしない。

# 14. 自動テスト必須項目

## 14.1 幾何計算

- 0度、90度、任意角度へ回転した指揮台の方向支持距離
- 1列目半径計算
- 列ごとの半径計算
- 1脚、2脚、奇数脚、偶数脚の角度配列
- 左右対称性
- 全列の開始・終了角度一致
- 方向角を変更した場合の回転移動
- 非有限値の拒否

## 14.2 重なり

- 中心間距離が直径未満なら重なり
- 直径と等しい場合は接触であり重なり扱いにしない
- 複数列間の重なり検出
- 既存オブジェクトとの判定

## 14.3 Reducer

- 合計脚数
- 1 Actionでの追加
- 全生成物選択
- Undo/Redo
- 非表示レイヤー拒否
- ロックレイヤー拒否
- 不正な指揮台ID拒否
- `type !== "podium"` 拒否
- 既存オブジェクト非破壊

## 14.4 回帰

- 既存 `ADD_PULT_ARC` の結果を変更しない
- 標準椅子の円形表示、プリセット寸法、ラベル、SVG／表示資産選択結果を変更しない
- 椅子円形化に関する既存テストを変更・削除せず通過させる
- 行列配置を変更しない
- 保存スキーマバージョンを変更しない
- PNG/PDF出力で通常の椅子として描画される
- 3Dビューで通常の椅子として扱われる

# 15. 手動確認項目

1. 実際の舞台図面で指揮台を配置し、多列円弧配置を起動する。
2. 方向指定がマウスとタッチの両方で直感的に行えることを確認する。
3. 端ハンドルを片側だけ動かし、反対側が対称に動くことを確認する。
4. 6脚・8脚・10脚の3列を配置し、左右端が放射方向上で揃うことを確認する。
5. 指揮台から1列目までの空きが中心方向上で1820mmになることを測定する。
6. 列中心間隔が910mmになることを測定する。
7. 意図的に円弧を狭め、重なり警告が出ても配置できることを確認する。
8. 配置後に端の椅子だけを手動移動できることを確認する。
9. Undo/Redoが一括単位で動作することを確認する。

11. PNG/PDF出力へプレビュー用ガイドやハンドルが含まれず、生成椅子が既存の円形椅子として出力されることを確認する。
